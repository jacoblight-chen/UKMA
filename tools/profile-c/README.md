# Profile C services (local, reproducible)

PostgreSQL + Qdrant + Neo4j for the profile-C parity runs (ADR-061). Everything is
downloaded, extracted and started **as the current user**: no administrator rights,
no Windows services, nothing installed outside `-Root` (default `F:\ukma-services`).

## Why scripts instead of a container

There is no Docker or Podman on the development machine, and the three servers all
ship portable Windows archives. The scripts therefore do what a compose file would
do — pin, verify, configure, start, wait for readiness — with the same guarantees
for reproducibility: **every artifact is pinned by version, URL and SHA-256**, and a
digest mismatch aborts the run instead of starting something unknown.

## Usage

```powershell
# first run downloads ~700 MB into F:\ukma-services, then starts everything
powershell -ExecutionPolicy Bypass -File tools\profile-c\start.ps1

# point the adapter tests at the services (writes tools\profile-c\env.ps1)
. .\tools\profile-c\env.ps1

cargo test -p ukma-adapter-postgres
cargo test -p ukma-adapter-qdrant
cargo test -p ukma-adapter-neo4j

# health table
powershell -ExecutionPolicy Bypass -File tools\profile-c\status.ps1

# stop everything (verifies the ports are free afterwards)
powershell -ExecutionPolicy Bypass -File tools\profile-c\stop.ps1
```

`start.ps1` is idempotent: a service that is already listening is reported and left
alone, so running it twice is safe. Without a service, the adapter tests skip and
pass — a machine with no servers must not fail the build, and must not claim
coverage either.

## What runs where

| Service | Version | Port | Credentials | Data |
|---|---|---|---|---|
| PostgreSQL | 16.4 | `127.0.0.1:55432` | user `postgres`, `trust` auth (localhost only) | `pgdata/` |
| Qdrant | 1.20.0 | `127.0.0.1:6333` (gRPC 6334) | none | `qdrant-data/` |
| Neo4j | 5.26.0 | `127.0.0.1:7474` (Bolt 7687) | `neo4j` / `ukma-dev-pass` | `neo4j-community-5.26.0/data/` |

Ports are deliberately not the defaults (`5432`/`7687`) so a locally installed
server never collides with these.

`tools/profile-c/env.ps1` is generated by `start.ps1` and sets:

```
UKMA_POSTGRES_DSN   host=127.0.0.1 port=55432 user=postgres dbname=postgres
UKMA_QDRANT_URL     http://127.0.0.1:6333
UKMA_NEO4J_URL      http://127.0.0.1:7474
UKMA_NEO4J_USER     neo4j
UKMA_NEO4J_PASSWORD ukma-dev-pass
```

## Security posture (deliberate, and limited)

- Every server binds to `127.0.0.1` only.
- PostgreSQL uses `trust` auth because the cluster is throwaway and loopback-only;
  that is a **development** choice, not a template for a deployment.
- Neo4j's password is a known development value, printed by `status.ps1`.
- The adapters treat configuration as the availability switch, so an unconfigured
  machine reports profile C unavailable and fails closed (ADR-038).

## Pinned artifacts

`versions.json` is the single source of truth: version, URL, SHA-256 and size for
each archive, plus the port map and the development credentials. To move a service
version, change it there and re-run `start.ps1`; the digest check makes an accidental
change visible immediately.

## Cleanup

```powershell
# stop, then delete everything the scripts created
powershell -ExecutionPolicy Bypass -File tools\profile-c\stop.ps1
Remove-Item -Recurse -Force F:\ukma-services
```
