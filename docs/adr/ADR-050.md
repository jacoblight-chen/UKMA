# ADR-050 Document Intelligence 服務實作決策（P4）

**Status: ACCEPTED**（owner 決策記錄，2026-10-25）
**Spec references:** §9.1、§31.4、§33.1、§33.2（State）、§33.3、§37、§40.4、§41.4
**Related:** ADR-048（O-02：無 OCR）、ADR-049（P3 code service 的同型決策）

## 1. Context

P4 要把 §33 的 14 個 document operation、三種格式的 parser 與 requirement/relation
抽取落地成可測試的 Rust 實作。實作過程遇到六個規格沒有完全決定、但會影響程式結構的點。

## 2. Decisions

| ID | 決策 | 理由與後果 |
|---|---|---|
| **D-01** | 同步核心 `DocumentService` ＋ §37 `async` trait `DocumentIntelligencePort`（async 方法直接 delegate） | 與 ADR-049 C-01 一致：只有一個 ABI 面，無 runtime 相依，P8 gateway 可直接 await |
| **D-02** | `completeness` **由 blocks 推導**，parser 不能自行宣告 | `finish_document()` 只要有 `parse_status != complete` 的 block 就回 `partial`。這讓「宣稱 complete 卻有 unparsed 區塊」在型別層面不可能發生 |
| **D-03** | 無 OCR（ADR-048 O-02）：影像區塊 = `unparsed` + `OCR_NOT_IMPLEMENTED` + `partial`；純影像頁另記 `PAGE_WITHOUT_TEXT` | 掃描式 PDF 不會被當成「空文件」默默成功；`parse_preview` 亦同 |
| **D-04** | Requirement 抽取只提供 **rule-based extractor profile `normative-keyword/1`**，一律 `candidate` / `unverified`；未知 profile → `MODEL_UNAVAILABLE` | 不引入 LLM 相依；不偽稱 approved requirement。`review_requirement` 是唯一能把狀態推進的路徑，且需要 evidence（`EVIDENCE_REQUIRED`）與 etag |
| **D-05** | span 語意依格式不同，且**明示**：Markdown/PDF 指向 artifact 的 byte offset（1-based line），DOCX 是**抽取文字的 offset**（段落序號為 line） | OOXML 沒有穩定的行概念；與其假造行號，不如在 parser 文件與 ledger 說明差異 |
| **D-06** | `redacted = true` 只代表「內容被保留未回傳」：由 `DocumentAuthorizer::redact` 政策，或呼叫端 `max_bytes` 不足以容納該 span | 絕不默默截斷後回傳半段文字（那會被誤讀為完整證據）。兩種情況都回 `text: null` |

## 3. 與 indexing-engine 的 FSM 對照

§33.2 列 `REGISTERED → PARSING → EXTRACTING → STAGING → COMMITTED → INDEXING → READY`；
`indexing-engine` 提供 `Queued → Parsing → Extracting → Resolving → Staging → Committing →
Indexing → Ready`。沿用 ADR-049 C-04 的處理：**同一 FSM 的縮寫**，
`REGISTERED ≙ Queued`、`COMMITTED` 表達為 `Committing` 階段的 commit phase，
`JobView.canonical_committed` 取自 commit phase 而非 stage（§40.4）。不新增第二個 FSM。

## 4. Known gaps（已記錄，未宣稱完成）

1. **`compare_code: true` 無 code 連結**：P4 服務未綁定 P3 code index，因此
   `verify_consistency` 把文件放進 `skipped_refs` 並回 `completeness=partial`，附上原因，
   不偽造 `stale_implementation` finding。
2. **無持久化**：`InMemoryDocuments` 與記憶體內 index 僅為開發／測試用；artifact 與
   parsed blocks 都保留在 index 中（`invalidate_revision` 為 stale-not-delete），但重啟即消失。
3. **PDF 只取文字層**：不做版面分析、表格重建或閱讀順序推斷；表格類 PDF 會被當成單一
   paragraph block。
4. **Requirement 未進入跨文件索引**：`document.search` 只搜 block 文字，不搜 requirement。
5. **DOCX 的 table/paragraph 巢狀**：目前 `w:tbl` 會產生 table block 與 cell blocks，
   但不重建 row/column 座標。
