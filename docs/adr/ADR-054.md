# ADR-054 Gateway 實作決策（P8）

**Status: ACCEPTED**（owner 架構審批，2026-10-25）

**Spec references:** §31.2、§31.4、§31.5、§36.4、§40.7（MCP-001、PROP-10、SYS-01..04、SEC-001、DB-009）
**Related:** ADR-034／ADR-035（單一 registry／單一 error 集合）、ADR-047（system operations）、ADR-049…ADR-053（四域服務）

## 1. Context

P8 交付 MCP tools、REST、SDK、CLI 與 server：把 P3–P7 的四個 domain 服務接上 §31.4 envelope
與 §31.5 error envelope。**沒有新增或修改任何 wire 級 operation**：69 個 operation
（65 domain + 4 system）的 id、scope、error 集合、idempotency/concurrency 宣告全部沿用
`contracts/api/operation-registry.yaml` 與 `ukma-contracts::generated`。

## 2. Decisions

| ID | 決策 | 理由與後果 |
|---|---|---|
| **D-01** | 只有**一個**來源：`ukma_contracts::generated::OPERATIONS`。`manifest`、`rest`、`error_codes`、`idempotency`、`concurrency`、`required_scopes` 全部投影自它；`drift()` 只做結構檢查且必須為空 | MCP-001／PROP-10；禁止第三份手寫清單。`ukma-contract-check` 仍獨立驗證 registry ↔ generated |
| **D-02** | AuthN 屬 host：`Gateway` 透過 `ScopeResolver` port 取得 principal 的實際 scope。預設 `EnvelopeScopes` 信任 envelope（**開發 profile**），`StaticScopes` 供測試與嵌入式使用；client 自報 scope 只作為 **期望**，不符時產生 warning，不影響授權 | §31.4「client 自報不是權威」。測試 `a_forged_envelope_scope_does_not_grant_authority` 固化 |
| **D-03** | **前置條件錯誤不正規化**：版本、operation 名稱、scope、idempotency、etag、limits、deadline、snapshot 這些 §31.4 通用規則的錯誤碼**原樣**輸出（例如 `TIMEOUT`）；**只有 handler（domain）結果**才與 `OperationSpec::error_codes` 比對 | registry 的 `error_codes` 描述的是 domain 結果，不是 envelope 規則；若把 `TIMEOUT` 正規化成 `INTERNAL` 會讓 client 誤判為不可重試 |
| **D-04** | 未宣告的 domain 錯誤碼**一律不外洩**：`INVALID_ARGUMENT` → `INVALID_SCHEMA`；`NOT_FOUND` → `FORBIDDEN`（若該 operation 宣告 `FORBIDDEN`）；其餘 → `INTERNAL`，並在回應 `warnings` 記錄原碼 | §31.5 closed set；同時讓 registry 的漂移**看得見**而不是被吞掉 |
| **D-05** | §40.7 落地：`memory_domain::CrossScopeDenied` 經 `DomainFailure` 映射為 `NOT_FOUND`（不是 `CROSS_SCOPE_DENIED`），因此跨 tenant 讀取不洩漏存在性；寫入類 operation 未宣告 `NOT_FOUND`，由 D-04 降級為 `FORBIDDEN`，同樣不洩漏 | 由整合測試抓到的真實缺陷（原本回 `INTERNAL` + warning）。相容性：屬於 gateway 對 domain 錯誤的呈現，未改動任何 operation 的 wire 語意 |
| **D-06** | `system.get_job`／`system.cancel_job` 由 gateway 的 `JobIndex` 實作，索引鍵為 **tenant+project+job_id**；cancel 為冪等（第二次回同一 cancelled 記錄），已過可取消階段才回 `JOB_NOT_CANCELLABLE` | §36.4；不讓 job 成為跨租戶可查資源。cancel 不會回滾已 commit 的 canonical 資料 |
| **D-07** | REST：所有 operation 都是 `POST /api/v1/{domain}/{operation}`（讀亦然），`GET` 僅 `/api/v1/health` 與 `/api/v1/jobs/{id}`；路徑與 body 的 `operation` **必須一致**，否則 `INVALID_SCHEMA` | §31.2；避免以路徑偷偷改寫 operation。job status 無 body，故 tenant/project/principal/scope 由 `x-ukma-*` header 供給，缺 tenant 或 project → `INVALID_SCHEMA` |
| **D-08** | HTTP status 映射為**伺服器選擇**（spec 只關閉 error code，未逐一綁定 status）：`INVALID_*`/`UNSUPPORTED_*`/`EVIDENCE_REQUIRED`/`CONSISTENCY_UNSUPPORTED`→400、`UNAUTHENTICATED`→401、`FORBIDDEN` 家族→403、`NOT_FOUND` 家族→404、conflict 家族→409、`CURSOR_EXPIRED`→410、`SOURCE_TOO_LARGE`→413、budget 家族→422、`*_UNAVAILABLE`／`INDEX_*`→503、`TIMEOUT`→504、其餘→500 | 以 RFC 9110 類別分組；`partial` 仍為 200（envelope 內表達）。這是可替換的投影，不是 wire 契約 |
| **D-09** | SDK 為 **schema-driven generic 層**：`Client::invoke`（raw）與 `Client::typed::<Q,R>`（依 registry 宣告的請求／回應型別）＋ 4 個 system helper；transport 是 port（`InProcess` 直接呼叫 gateway）。**不產生 69 個手寫方法** | 型別一致性由「呼叫端提供 operation 的宣告型別」保證；手寫 69 個方法會製造第二份來源與漂移風險 |
| **D-10** | Legacy CodeGraph alias **預設 inert**：0 alias、`is_enabled()=false`、`resolve()=None`；`enable()` 需要（a）pinned commit `590c2ca7dd7b37bd1d41caf45fac535b6522f969`、（b）每個 alias 的 parity test、（c）目標 operation 已註冊 | §36.4；不得宣稱相容。`difference_matrix_json()` 明載 `enabled=false`、`alias_count=0` |
| **D-11** | Server 與 CLI 都只透過 gateway 派送，不直接觸碰任何 domain service 或 storage port | 保證授權、idempotency、error 正規化只有一條路徑；CLI 的 `--tenant/--project/--scope` 只影響 envelope 期望值 |

## 5. 已知缺口（不得宣稱完成）

1. **無持久化**：job 索引、sessions、所有 domain state 都在記憶體；重啟即消失。
2. **認證為開發 profile**：預設信任 envelope 的 scope；尚未接上真實 IdP／token 驗證與 `delegation_token` 驗證（`DELEGATION_EXPIRED` 只在 domain 邊界出現）。
3. **legacy alias 全數未啟用**：0 alias、無 parity evidence，因此不得宣稱與 CodeGraph MCP 相容。
4. **無 streaming／SSE、無 rate limiting、無 TLS**：listener 為單執行緒 `std::net`，每連線一個請求。
5. **SDK 未產生 69 個具名方法**（D-09）：型別安全由泛型 `typed::<Q,R>` 提供。
6. **JSON Schema 仍為 preliminary**：manifest 覆蓋 ≠ schema closure（§31.3.1）。
7. **HTTP status 映射非規範**（D-08）：不同實作可採不同分組而不違反 wire 契約。

## 6. 未變更的東西

- `contracts/api/operation-registry.yaml`、`error-registry.yaml`：未新增／刪除任何 operation 或 error code。
- §31.4／§31.5 envelope 與 error envelope 語意未變更。
- 沒有引入資料庫 SDK 或 HTTP framework；`ukma-mcp` 依賴 serde／serde_json 與四個 domain crate，`ukma-server`／`ukma-cli` 只依賴 `ukma-mcp` 與 `ukma-contracts`。
