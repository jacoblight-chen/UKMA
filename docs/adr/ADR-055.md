# ADR-055 跨域整合、安全與 Chaos 實作決策（P9）

**Status: ACCEPTED**（owner 架構審批，2026-10-25）

**Spec references:** §17.1、§29.4、§38.1、§38.2、§38.3、§40.7（E2E-API-01..12、PROP-01..10、MCP-001、SEC-001）
**Related:** ADR-049…ADR-054（四域服務與 gateway）、ADR-022（capability 缺口不得靜默降級）

## 1. Context

P9 的目標不是新增 wire operation（registry 仍為 69 個：65 domain + 4 system），而是
**證明既有實作在跨域組合、惡意輸入與崩潰重播下仍然成立**：

- §38.1 12 個 E2E scenario
- §38.2 10 個 property
- §17.1 29 項強制測試與 §29.4 40 項 fault matrix 的處置
- 崩潰於 canonical commit 後、projection publish 前的重播

新增 crate：`crates/ukma-integration`（測試專用，`publish = false`）。

## 2. Decisions

| ID | 決策 | 理由與後果 |
|---|---|---|
| **D-01** | E2E 一律走 **public API**：測試建 envelope → `Gateway::dispatch` → 讀 response envelope。只有兩個沒有 wire operation 的目的地（storage ports、graph query facade）由測試直接驅動，並在矩陣中標明是 adapter-level | 讓 E2E 證明的是「契約可達」，不是「內部函式可呼叫」。若日後 gateway 改變 envelope 規則，E2E 會失敗 |
| **D-02** | harness 提供 `Env::dispatch` 自動補 `idempotency_key`（每次呼叫唯一）與 `expected_etag`，但**只在呼叫端未指定時** | §31.4 對多數 mutation 宣告 idempotency/etag；若每個 scenario 手動填序號，會製造跨 operation 的 key 碰撞（fingerprint 含 operation 名，會變成 `IDEMPOTENCY_CONFLICT`） |
| **D-03** | `all_scopes()` = registry scopes ∪ domain 內部 seam scopes（`trace:admin`、`code:index_admin`、`document:index_admin`） | §40.7 的 endpoint/head 觀測是 seam 而非 wire operation（ADR-053 D-13），但測試仍需以真實 scope 授權 |
| **D-04** | Traceability 的 link 方向固定為 **`source = code/target = requirement`**，`kind = IMPLEMENTS` | `analysis::coverage` 以 `link.target.id == requirement.id` 配對；coverage 端到端測試因此可驗證 denominator/numerator |
| **D-05** | 覆蓋矩陣是**機器可讀檔案** `contracts/testing/test-coverage.json`，由 `coverage_matrix.rs` 驗證：每個 ID 恰好分類一次、`gap` 必須有原因、`covered`/`partial` 必須引用**真實存在**的測試函式 | 矩陣本身是 gate：把 gap 改成 covered 而不寫測試會讓 build 變紅。這也是「不得宣稱完成」的可執行版本 |
| **D-06** | 處置只有三種：`covered` / `partial` / `gap`，且 `partial` 必須寫明未覆蓋面 | 避免二分法逼出虛假聲明；目前 69 項中 covered 59、partial 5、gap 5 |
| **D-07** | ARC-001/DB-001 以**解析 workspace `Cargo.toml`** 實作：禁用 backend SDK 清單、禁止 domain crate 依賴 adapter、禁止 crate cycle | 這是唯一能在 Rust 測試內自動化的「無非法 Vendor SDK／無循環依賴」檢查；也讓 `DB-008`（無 RocksDB）有第二道防線 |
| **D-08** | DB-002 以**同一份 contract 函式**跑 `InMemoryGraphStore` 與 `FileGraphStore` | 「兩種獨立 adapter 跑相同 GraphPort 測試」被實際執行，而不是以 in-memory 假稱可攜性（§17.1 DB-01 的告誡） |
| **D-09** | Chaos 測試把崩潰點寫成註解並**用檔案重開模擬行程死亡**（`EmbeddedStore::open` 重新載入同一 snapshot），replay 前先檢查 `GenerationPointer::current()` 再 publish | 重複 publish 會把同一 generation 推進 `retained`（幽靈世代），所以冪等 publish 必須顯式判斷，測試即固化此規則 |
| **D-10** | 沒有把 §29.4 全部標成 covered：4 個相依於尚未實作的元件（migration、benchmark、第二個活後端、restore 演練）記為 `gap`，2 個跨域面記為 `partial` | 依 ADR-022：能力缺口必須明示。宣稱 69/69 全綠會是虛假聲明 |

## 5. 測試過程中發現的契約缺口（已記錄，未擅自變更 wire 語意）

1. **Traceability 的 wire enum 是 UPPER_SNAKE**（`IMPLEMENTS`、`VERIFIES`），而 §34.1 對 memory 要求 lowercase；
   `contracts/schema/v1/traceability.*.request.schema.json` 對 `TraceLinkInput` 仍是 `UNRESOLVED TYPE`，
   因此無法由 schema 仲裁。**待架構審批**後才能統一，測試目前依實作使用 UPPER_SNAKE。
2. **`code.find_symbols` 未宣告 `NOT_FOUND`**：對未分析過的 commit 查詢，domain 回 NotFound，
   gateway 依 D-04（ADR-054）降級為 `FORBIDDEN`。語意上應是 `SOURCE_UNAVAILABLE`／`INDEX_NOT_READY`。
3. **`Symbol.definition.revision` 是 `worktree`** 而非 commit SHA，因此「exact commit」只能由
   analysis job／manifest 承載，symbol 本身不帶 commit 綁定。
4. **`memory.commit_reconsolidation` 未宣告 `EVIDENCE_REQUIRED`**：缺 evidence 時被正規化為 `INTERNAL`。
5. **`memory.close_agent_scope` 回傳 `stage = "sealed"`**（`AgentStatus::Sealed`），與 `closed: true` 語意重疊，
   文件需說明兩者關係。
6. **`memory.consolidate` 不支援請求層 idempotency**：同內容重放會建立新 job（階段層 replay 才是冪等的），
   因此 E2E 改以「promote 後事實數不變」證明冪等。
