# ADR-031 — S1 Graph Contract Decisions (Canonical IDs, Capability Error, Node/Edge Wire Names)

**Status: ACCEPTED** (by owner instruction, 2026-10-25)
**Scope:** S1 Graph Engine vertical slice (`ukma-graph-engine`, to be created after S1 gate).
**Supersedes:** nothing. **Amends:** nothing in UKMA v1.2.3 (no established semantics are
changed — see §4). The 65-operation registry is preliminary; **65/65 closure is NOT claimed.**

## 1. Context

S1 (Graph Engine Migration) requires three contract decisions that were pending
architecture approval (`s1-contract-proposal.md` §6). This ADR resolves them with
normative grounding from UKMA v1.2.3:

- Spec: `export type ID = string` (all IDs are strings).
- **ADR-023 (ACCEPTED):** "Logical IDs、Revision、ACL、Provenance、Relation semantics
  必須跨 backend 不變" — logical IDs must not vary across backends.
- **PROP-02:** stable logical identity does not change with backend schema or query order.
- **PROP-03:** graph cycles / cross-project edges / oversized traversals must have
  deterministic bounded termination.
- Error registry: `CAPABILITY_UNAVAILABLE` is a registered ErrorCode
  ("Adapter/Model 不支援 | no | 停止或受政策降級"; non-retryable).
- Established ID pattern in contract tests: `"symbol:one"` (structured, colon-separated).
- Enum wire convention in `ukma-contracts`: `#[serde(rename_all = "snake_case")]`.

## 2. Decisions

### D1 — Canonical ID format: structured string, engine-assigned, persisted

- Canonical node ID: `graph.node.<ULID>` (ULID = 26-char Crockford base32, time-ordered).
- Canonical edge ID: `graph.edge.<ULID>`.
- Generated by the engine **at creation** via an injectable `IdGenerator` trait
  (default: SystemTime + counter + hash-mix; tests inject a deterministic generator).
- Persisted as part of the canonical record — therefore **stable across adapter
  substitution** (ADR-023, PROP-02): swapping Memory → JSON → any future adapter
  never changes external IDs.
- Upstream `NodeId/EdgeId = u64` monotonic counters are **vendor-internal storage
  detail, never exposed** (mitigates risk R1).
- Golden parity (`tests/golden/graph-basic-ops.golden.json`) is asserted on
  **structure** (counts, edge topology, traversal shape) with canonical-ID mapping
  via deterministic ordering — never on raw u64 values.

### D2 — CAPABILITY_UNAVAILABLE: use the spec-registered code as-is

- Non-portable features the active adapter cannot provide return
  `ErrorDetail { code: "CAPABILITY_UNAVAILABLE", retryable: false }` — the exact
  registered registry value; **no new wire code is invented**.
- Adapters declare capabilities (ADR-022 capability negotiation); the engine probes
  before use (spec §: capability values come from real probes, not config claims).
- This is *usage* of an established registry value, not a change to it.

### D3 — NodeType/EdgeType wire names: new addition, v1, snake_case

- The 65-operation registry contains **no graph operations**, so no established wire
  semantics exist for graph node/edge types — D3 is an **addition**, not a
  modification (no v1.2.3 semantics are altered).
- v1 adopts the upstream-observed semantics (8 node types, 12 edge types, 3
  directions) with the UKMA snake_case wire convention:
  - Node: `code_file`, `function`, `class`, `module`, `variable`, `type`,
    `interface`, `generic`
  - Edge: `imports`, `imports_from`, `contains`, `calls`, `invokes`, `instantiates`,
    `extends`, `implements`, `uses`, `defines`, `references`, `runtime_calls`
  - Direction: `outgoing`, `incoming`, `both`
- Versioned (`graph_types_v1`); unknown values are rejected on deserialization
  (UKMA `deny_unknown_fields` convention) — no silent widening.
- Upstream PascalCase names are preserved in the source-migration manifest as the
  mapping provenance (observed upstream → UKMA wire name).

## 3. Consequences

- `ukma-graph-engine` depends on `ukma-contracts` only (no database dependency;
  RocksDB, if ever added, is an optional feature-gated adapter outside Domain).
- Traversal API must enforce **bounded, deterministic termination** (PROP-03):
  `max_depth`/`max_nodes` bounds are mandatory parameters with hard limits;
  deterministic ordering (sorted adjacency) is required for replayable results.
- `IdGenerator` is injectable → deterministic contract tests (no RNG dependency).
- A `CanonicalId` newtype validates the `graph.node.`/`graph.edge.` format at the
  type boundary (invalid format → `INVALID_ARGUMENT`).

## 4. What this ADR does NOT do

- Does not modify any established UKMA v1.2.3 wire semantics or the 65-operation
  registry (per spec rule: changing ADR-021~030 requires a superseding ADR +
  migration — none is triggered here; D2/D3 are usages/additions).
- Does not claim 65/65 registry closure.
- Does not approve S1 code start — S1 implementation proceeds per the owner's
  explicit instruction with this ADR's decisions in force.
