# ADR-058 — Wire payload schemas are generated from the Rust types

- Status: accepted
- Date: 2026-10-25
- Supersedes: the "schemas are preliminary" caveat recorded in ADR-008/ADR-047 and repeated in
  ADR-054 … ADR-057
- Related: ADR-047 (system API), ADR-054 (gateway), ADR-057 (remaining gaps, §6 lists the four
  open decisions this ADR now settles)

## 1. Context

The 138 operation schema files under `contracts/schema/v1` were hand-written from the normative
markdown tables. 30 of them still carried `$comment: "UNRESOLVED TYPE: …"` on the request `input`
and 39 carried `"RESPONSE TYPE NOT CLOSED: …"` on the response `data`. Those placeholders meant the
published machine-readable contract said nothing about the payload: a client could send
`{"input": {"input": null}}` and be schema-valid while the gateway rejected the request. The owner
approved full closure ("`full`" option in ADR-057 §6): expand the unresolved types, unify enum
casing, add `required`/bounds and prove the closure with fixtures.

Hand-writing 130 payload schemas was rejected: it re-creates the same drift the placeholders came
from, and the authoritative description of the payload already exists — the Rust structs the MCP
gateway decodes with `serde_json::from_value` and encodes with `serde_json::to_value`.

## 2. Decision

1. **The Rust wire types are the single source of truth.** `tools/wire-schema`
   (`ukma-wire-schema`) derives `schemars::JsonSchema` for every request and response type and
   emits `contracts/schema/v1/wire.schema.json`:
   - `$defs`: 184 definitions, one per Rust type reachable from a payload;
   - `x-operations`: `operation_id → {request, response}` for all 65 domain operations.
2. **Derives are feature-gated.** Each domain crate exposes an optional `schema` feature
   (`schema = ["dep:schemars"]`) and every wire type carries
   `#[cfg_attr(feature = "schema", derive(schemars::JsonSchema))]`. The default build is
   unchanged: no schemars in the shipped dependency graph of the binaries, no runtime cost.
3. **Envelopes reference, they do not duplicate.** For the 65 domain operations the request
   `input` and response `data` properties are now
   `{"$ref": "wire.schema.json#/$defs/<Type>"}`. The envelope invariants (§31: `api_version`,
   `operation`, `context`, `status`, `warnings`, `partial_reasons`, `freshness`, and the
   `if/then` rules that make `ok ⇒ data` and `error ⇒ error`) are unchanged.
4. **Two namespaces, no shadowing.** `wire.schema.json` and `shared.schema.json` describe two
   different universes (payload types vs envelope types) and both define e.g. `Span` and
   `ScopeRef`. `ukma-contract-check` therefore composes refs as `#/$defs/wire.<Name>` and
   `#/$defs/shared.<Name>` instead of flattening both maps into one namespace, where the second
   file silently overwrote the first.
5. **Name collisions are resolved in Rust, not in JSON.** Where two crates declare a type with
   the same simple name and a different shape (`PageRequest`, `JobHandle`, `JobView`, `JobHandle`,
   `ChangeReceipt`, `CancelJob`, `GetJob`, `Ref`, `Evidence`, `BlockKind`, `Symbol`) the generator
   fails with `definition X is claimed by two different Rust types`; the resolution is a
   `#[cfg_attr(feature = "schema", schemars(rename = "<Domain><Name>"))]` on one of the two.
6. **Drift is a test failure.** `ukma-wire-schema` asserts that the checked-in
   `wire.schema.json` equals `build()`, that every registry operation has both types, that every
   definition is reachable from an operation, and that no `UNRESOLVED`/`NOT CLOSED`/`PROVISIONAL`
   marker or unrewritten `#/definitions/` pointer survives.
7. **`ukma-contract-check` gained gate `SCHEMA-03`**: every operation payload must be a typed
   schema (a `$ref`, or — for the four system operations — an object with declared properties),
   the wire types of the 65 domain operations must exist, the fixture suite must validate against
   them, every `contracts/mcp/tools/*.input.schema.json` must equal the composed canonical request
   schema (the MCP manifest can no longer advertise an untyped payload; each tool schema
   inlines only the definitions its payload reaches, 69 files / 0.33 MB instead of 12.7 MB
   when every `$defs` entry was copied), and no file under
   `contracts/schema/v1` or `contracts/mcp/tools` may contain `UNRESOLVED TYPE`, `NOT CLOSED` or
   `PROVISIONAL`.

## 3. Consequences

- `cargo run -p ukma-contract-check` reports **5411 checks, 0 failed** (was 4745). The 666 new
  checks are the payload-typing, wire-definition, MCP-tool-schema and placeholder assertions.
- The valid request/response fixtures for the 65 domain operations were regenerated from the
  schemas instead of hand-written, so a payload example can no longer drift from its schema.
  The negative fixtures (4 per operation, 276 files) are untouched and still rejected.
- Enum casing is now *documented reality* instead of an ambiguity: `TraceKind` is
  `SCREAMING_SNAKE_CASE` (`IMPLEMENTS`, `VERIFIES`, `SPECIFIES`, `REFERENCES`, `CONTRADICTS`,
  `DERIVED_FROM`) because that is what the implementation serves and what every test asserts,
  while the memory enums (§34.1) are `snake_case`. Changing either would be a wire-breaking
  change and needs its own approval; ADR-058 records the split rather than silently picking one.
- `title` strings no longer say `[PHASE2 PROVISIONAL]` / `(provisional system API — ADR-047)`;
  the schemas are the closed contract now.
- The dependency set grew by `schemars` + `schemars_derive` + `serde_derive_internals` +
  `dyn-clone` (all MIT, four crates). The licence inventory and CycloneDX SBOM were regenerated:
  **336 packages (307 external, 29 workspace), 0 unlicensed, 0 blocked**, digest refreshed.
  `cargo test -p ukma-integration --test release_evidence` re-derives every decision from
  `Cargo.lock` and passes.
- Validation evidence (all executed on 2026-10-25, Windows x86_64, `stable` toolchain):
  - `cargo fmt --all -- --check` → clean
  - `cargo check --workspace --all-targets` → clean
  - `cargo clippy --workspace --all-targets -- -D warnings` → clean
  - `cargo test --workspace --all-targets` → **683 passed, 0 failed** across 69 targets
  - `cargo run -p ukma-contract-check` → **5411 checks, 0 failed**
  - `cargo run -p ukma-wire-schema -- --check` → up to date

## 4. What this does not claim

- `claim_level.implementation_compliant` stays **false** and `production_ready` stays **false**.
  Schema closure means the contract is machine-readable, complete and enforced — not that every
  §-level behaviour is proven.
- The generation covers payload types, not the *semantics* of a field: a schema cannot express
  "this etag must match the current head". Those invariants live in the state machines and are
  covered by the contract tests, not by the JSON Schema.
- Profile C parity (PostgreSQL + Qdrant + Neo4j), SBOM signing (no key) and FM-006 (canonical
  schema migration) remain open, unchanged by this ADR.
