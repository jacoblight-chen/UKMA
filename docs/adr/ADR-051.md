# ADR-051 Fractal Memory 核心實作決策（P5）

**Status: ACCEPTED**（owner 架構審批，2026-10-26）

**Spec references:** §10.2、§21、§22、§23、§26.4、§34.1、§34.2、§37、§40.2
**Related:** ADR-021（Database-Agnostic）、ADR-022（能力缺口必須回報）、ADR-034/035（不得第二套 registry/error）、ADR-048（BGE-M3 profile）、ADR-049（P3 服務形狀）、ADR-050（P4 文件服務）

## 1. Context

P5 交付 §34 的 Fractal Memory core operations：MAPI-01..09、13..17、23..25（共 17 個）。
本次沒有新增 wire 級 operation、沒有改動 65-operation registry，也沒有改動 §31.4 全域語意。

`crates/memory-domain` 由 skeleton 變為可編譯、可測試的垂直切片；演算法一律取自既有 `context-engine`（budget、folding、eviction、paging）與 `retrieval-engine`（RRF、recency、final score、BM25、cosine），**不新增第二套實作**。

## 2. Decisions

| ID | 決策 | 理由與後果 |
|---|---|---|
| **D-01** | `MemoryKind` 等列舉的 wire 形式採 **§34.1 小寫**（`working`/`episodic`/`semantic`/`procedural`、`paged_out`、`timed_out`） | §21.1 的 envelope 範例寫 `"WORKING"`，但 §34 是本 Domain 的 normative catalog；衝突以 §34 為準，並在此記錄，未修改 §21 |
| **D-02** | Context budget／folding 三級／eviction 雙策略／paging 全部 **reuse `context-engine`**；BM25 與 cosine **加入 `retrieval-engine`** 而非在 memory 內另寫 | §22.1／§29.3 要求唯一實作；BM25 與 cosine 屬共用檢索框架（UNIFIED），故落在 retrieval-engine（`Bm25Index`、`cosine`，皆有測試） |
| **D-03** | 本 build **沒有摘要模型**：`fold` 產生**抽取式** digest（保留所有 key facts 與全部 evidence 參照）；safety rule 命中時 `forced_preserve = true` 且輸出**無損**；若無損輸出超過 `max_tokens` 回 `POLICY_DENIED`，**不截斷** | §22.2 R1–R8 + §28.3「Folding 失敗 → 返回未壓縮安全摘錄或 budget error」；不以假摘要冒充模型輸出 |
| **D-04** | FSRS/TTL 公式原樣實作：`R(t)=[1+(19/9)(t/S)]^-1`、`S_new=min(S*[1+0.5(11-D)(e^{1.5(1-R)}-1)],3650)`、失敗 `max(0.1,S*0.5)`、`T_active(d)=max(1h,72h/2^d)`、`effective_active_until=min(creation+T_active, completion+1h)`；`t` 用 UTC 秒差且 **負值拒絕**（clock skew 隔離） | §23.1／§23.2；時間以 `time` 模組自帶 RFC 3339 parser（不引入日曆依賴），解析與算術皆有測試 |
| **D-05** | 熵訊號用**真實 gzip**比率（`flate2`，預設等級、mtime 0，可重現），門檻 `0.4`；空內容回 `SKIPPED_EMPTY` | §23.3 的定義就是 `gzip_size/raw_len`；不用近似模型替代 |
| **D-06** | `memory.search` 以 **BM25 lexical 通道為權威**，vector 通道只在有 embedding profile 時執行；缺模型時回報 `skipped=(vector, MODEL_UNAVAILABLE…)` 並視為 `partial`；`novelty_bonus` 本 build 無模型，固定 `1.0` 並**記錄於 `defaults`** | §24.1 不准把策略失敗偽裝成零結果；§24.2「缺失量採有記錄的預設值」；不宣稱 recall／MRR 品質 |
| **D-07** | 隔離單位：**working/episodic = tenant+project+session+agent（sandbox）**，**semantic = tenant+project**；跨 sandbox 讀取回 `CROSS_SCOPE_DENIED`；`close_agent_scope` 只回 `FoldedResult + evidence refs + status` | §26.4／§34.3；父代理不隱式取得子代理 WM/EM，fold 由 close-scope 內部收集該 child scope 後執行 |
| **D-08** | pin 與 legal hold **不是** wire operation：由政策面（P6/P7）透過 `set_episode_protection` seam 套用；`forget` 遇 hold 回 `DELETION_BLOCKED`，遇開啟中的 reconsolidation window 回 `POLICY_DENIED` | §22.2 R6/R8 是政策旗標；保留 seam 使規則可達且可測，且不新增未經批准的 operation |
| **D-09** | P6 的 8 個 operation（MAPI-10..12、18..22）在 §37 port 中**存在**但回 `CAPABILITY_UNAVAILABLE` | ADR-022：能力缺口必須明示，不得回空成功；port 完整 25 方法，行為缺口誠實標記 |
| **D-10** | `MemoryService` 為 sync core + delegating `async` §37 port（`#[allow(async_fn_in_trait)]`），與 P3/P4 同一 ABI | ADR-049 C-01；單一 ABI，gateway 端 `await` |
| **D-11** | 墓碑順序：**tombstone → 每個投影撤銷 → cache 失效**；`DeletionReceipt.projections` 只含索引投影，`source_artifact`／`code_document_knowledge`／`accepted_trace_link` **永不撤銷**（恆等於 `deletion::NEVER_REVOKED`，以測試守門），受影響的 accepted link 改標 stale | §34.2 `forget` 註記、§21.1「先 tombstone 後重建索引」、PROP-05 |
| **D-12** | `Page::of` 會先 `validate()` page request（`limit ∈ 1..=200`） | 與 P4 的差異：P4 由 service 驗證；此處在型別層驗證，避免 0-limit 產生無意義游標 |

## 5. 已知缺口（不得宣稱完成）

1. **無持久化 adapter**：working/episodic/page/window 全部在記憶體投影；重啟即失去（與 P3/P4 一致，adapter 屬後續階段）。
2. **sweep 尚未排程**：`MemoryService::sweep` 是可重複執行的 pass，但 `ttl_sweep`／`fsrs_refresh` 等 Job 排程屬 P6-WP7。
3. **語意記憶與程序記憶未實作**：`MemoryKind::Semantic/Procedural` 型別與 port 方法存在，但無 `propose_fact` 等行為（P6）。
4. **無九階段 consolidation DAG**（P6-WP1）、**無 trust 數學**（P6-WP3）、**無多語言對齊與 translation cache**（P6-WP5）。
5. **RL eviction 仍為 shadow**：無模型權重，`model_profile = "shadow-no-model"`，永不繞過 deterministic 篩選。
6. **`novelty_bonus` 固定 1.0**（已記錄於搜尋報告），無 novelty 模型。
7. **§21.5 `EmbeddingProfile` 未另立型別**：沿用 `embedding-engine::ModelProfile`／`EmbeddingPort`，避免第二套 profile 定義。
8. **`full_text_ref` 未經 ArtifactStore 授權檢查**：目前只保存參照，讀取全文的 ACL 重驗屬 adapter/ArtifactStore 階段（§28.1「讀取 Source Artifact 需重做 AuthZ」）。
9. **`task_id` 目前由 `ScopeRef.workspace_id` 帶入、缺失時為 `task-unspecified`**：真正的 task 綁定屬 gateway/E2E 層。

## 6. 未變更的東西

- `contracts/api/operation-registry.yaml` 未新增／刪除任何 operation。
- §31.4 的全域語意、§31.5 的 error/event envelope 未變更。
- 沒有引入任何資料庫 SDK；`memory-domain` 依賴只有 serde、sha2、flate2 與三個 in-repo engine/contract crate。
