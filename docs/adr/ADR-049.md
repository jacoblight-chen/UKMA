# ADR-049 Code Intelligence 服務實作決策（P3）

**Status: ACCEPTED**（owner 決策記錄，2026-10-25）
**Spec references:** §7.1、§31.4、§32.1、§32.1（State）、§32.3、§37、§40.4、§41.4
**Related:** ADR-031a（S1 graph 決策）、ADR-037（commit/projection 分離）、ADR-048（O-01 38 語言）

## 1. Context

P3 需要把 §32 的 13 個 code operation、ingestion 管線與 impact/edit-context 落地成可測試的 Rust
實作。實作過程遇到六個規格未完全決定、但會影響程式結構的點。本 ADR 只記錄**實作決策與
已知落差**，不變更任何已正式確立的 wire-level API 語意。

## 2. Decisions

| ID | 決策 | 理由與後果 |
|---|---|---|
| **C-01** | 同步核心 `CodeIntelligenceService`（inherent methods）＋ §37 `async` trait `CodeIntelligencePort`，async 方法直接 delegate 到同步核心 | §37 要求「擇一 ABI、不得混雜」：本階段只有一個 ABI 面（async trait），內部同步核心不另外暴露成第二個 trait。無 runtime 相依（測試以 `Waker::noop()` 自製 `block_on` 執行）。P8 gateway 可直接 await，不需 blocking adapter |
| **C-02** | Code index 是 **derived projection**；權威artifact 是 source snapshot + `CodeAnalysisManifest` | §32.3。`invalidate_revision` 只改 `stale` 旗標與 etag，**不刪除**歷史內容或 manifest（stale-not-delete）。尚未接入 canonical `GraphStore`，接線屬 P10 profile 工作，於此明確記錄為落差 |
| **C-03** | Symbol id 採 §32.3 version-scoped identity：`sha256(repo, commit, path, qualified_name, kind, signature, span)` → `sym:v1:<hex>` | 跨版 rename 因此必然是新 id（`possible_same_as` 候選），不會原地替換；同一 revision 在兩個 service 實例得到相同 id（已測試）。parser 端 `sym:<file>:<qualified>` 僅為 local id，service 於 `index_parsed` 重新映射 |
| **C-04** | Job FSM 直接重用 `indexing-engine`（§7.5 8 階段，含 `EXTRACTING` / `COMMITTING`） | §32.2 的 State 列為 `QUEUED → PARSING → RESOLVING → STAGING → COMMITTED → INDEXING → READY`，與 §7.5 為**同一 FSM 的不同縮寫**：§7.5 是 §32.2 的 superset（多 `EXTRACTING`，並把 `COMMITTED` 表達為 `Committing` 階段的 commit phase）。不新增第二個 FSM；`JobView.canonical_committed` 取自 commit phase 而非 stage（§40.4） |
| **C-05** | `ImpactReport.unresolved_dynamic_calls` 只計 **真正 `unresolved`** 的 call edge；任何 `static_possible` call 或深度截斷都會使 `completeness=partial` | §32.1「動態呼叫必須表達為 static_possible/unresolved，不可偽稱完整 call graph」。把 `static_possible` 計入 `unresolved_dynamic_calls` 會混淆兩種語意，因此拆開：計數只算 unresolved，complete 判定另計 possible |
| **C-06** | traversal（CAPI-07/08/09）**永不跟隨 `defines` 邊** | containment 是結構關係，不是引用；跟隨它會讓「callers of X」包含定義 X 的 module。`edge_kinds` 為空時代表「所有非 containment 邊」 |

## 3. Known gaps（不阻擋 P3 結構收尾，但不可宣稱完成）

1. **7 個語言在鎖定基線沒有可用 grammar**：`cobol, dart, dockerfile, perl, r, tcl, zig` 在
   上游 `Cargo.lock` 沒有對應的 `tree-sitter-*` crate。依 §4.2「不得用浮動 main、必須鎖定
   baseline」，這 7 個語言目前維持 `NotPorted`，且**未**引入非基線 crate。是否改以原生
   extractor 或核准非基線 grammar，需要 owner 決策（見 §4）。
2. **跨檔名解析未實作**：parser 只在同一檔案內比對呼叫名稱，因此跨檔 call edge 為
   `unresolved`。這使 impact 分析不會追蹤跨檔 caller（誠實地呈現為 partial）。
3. **Code index 尚未寫入 canonical GraphStore**：目前為 service 內建投影，重啟即消失；
   重建來源為 source snapshot + manifest。
4. **`analyze_repository` 為單行程同步執行**：`submit_analysis` + `run_analysis` 已分離，
   但尚無 worker/queue；P8 由 worker 呼叫 `run_analysis` 即可，不需改 operation 介面。

## 4. Open decision（需要 owner 決定，未自行決定）

**O-08：** 上述 7 個語言的處理方式 —
(a) 以原生 extractor（自寫 lexer/parser，僅覆蓋 ledger 的 `required_behaviour` 子集），
(b) 核准引入非基線 `tree-sitter-*` crate 並在該語言的 ledger slice 記錄 deviation，
(c) 明確標記為 `NOT_IMPLEMENTED` 並從 §32 的 38 語言宣稱中排除。

未決定前，`s2_parity_report.yaml` 對這 7 個語言的 `reason` 保持「no grammar in the locked
baseline」，不得改為 `Ported`。
