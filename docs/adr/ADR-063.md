# ADR-063 — MIG-01 permanent decision: the eight grammar deviations

- Status: accepted
- Date: 2026-10-25
- Closes the open decision ADR-049 O-08 and the `MIG-01` gate
- Related: ADR-049 (S2 baseline lock + O-08), docs/migration/s2-status.md, docs/migration/ledger/

## 1. The decision

ADR-049 O-08 left the handling of the languages that cannot use a grammar from
the locked baseline as an open decision. **MIG-01 is closed with option (b)** —
a pinned, non-baseline `tree-sitter` grammar crate, the deviation recorded in
the language's ledger slice — for every such language, plus the approved
`tree-sitter-kotlin-ng` fork. Nothing floating `main` is used; every crate is
version-pinned and ABI-compatible with the locked `tree-sitter 0.25.10`
through `tree-sitter-language`.

The eight deviations, as recorded in the ledger slices:

| Language | Deviation | Why the baseline cannot be used |
|---|---|---|
| cobol | `arborium-cobol 2.18.2` | no grammar in the locked baseline `Cargo.lock` |
| dart | pinned non-baseline grammar crate | no grammar in the locked baseline `Cargo.lock` |
| dockerfile | pinned non-baseline grammar crate | no grammar in the locked baseline `Cargo.lock` |
| perl | pinned non-baseline grammar crate | no grammar in the locked baseline `Cargo.lock` |
| r | pinned non-baseline grammar crate | no grammar in the locked baseline `Cargo.lock` |
| tcl | pinned non-baseline grammar crate | no grammar in the locked baseline `Cargo.lock` |
| zig | pinned non-baseline grammar crate | no grammar in the locked baseline `Cargo.lock` |
| kotlin | `tree-sitter-kotlin-ng 1.1.0` | baseline `tree-sitter-kotlin 0.3.5` links `tree-sitter >=0.21,<0.23`, which cannot coexist with the locked `0.25.10` |

Each slice's `changes` carries a `kind: deviation` entry that names the crate,
the version, the ABI path (`tree-sitter-language`) and the reason, so a
reviewer can reconstruct the decision without reading this ADR. The parity
claim for these eight languages is measured against the golden fixture
recorded in the slice, **not** against upstream behaviour, because the
upstream baseline has no comparable grammar to diff against.

## 2. What this does and does not claim

- It claims: for these eight languages the extractor runs through the shared
  generic `tree-sitter` engine, emits the same output shape as every other
  ported language, and its `required_behaviour` list is proven by the golden
  fixture (symbol identity, 1-based spans, containment/import/call edge kinds
  and resolutions, diagnostics on unparsable input).
- It does not claim: cross-file/cross-crate name resolution, macro expansion
  or type inference for any language; call edges stay `static_possible` or
  `unresolved` and are never `static_exact`. The seven "no baseline grammar"
  languages are additionally not a claim of equivalence with the upstream
  CodeGraph behaviour, because the upstream baseline never shipped a grammar
  for them.

## 3. Why (b) and not (a) or (c)

- **(a) native extractor** — a hand-written lexer/parser per language would be
  eight bespoke extractors to maintain, each covering only a subset of the
  ledger's `required_behaviour`. The shared engine plus a pinned grammar
  reaches the same coverage with one code path.
- **(b) pinned non-baseline grammar** — chosen. It keeps the §4.2 rule
  "no floating main, lock the baseline" intact (the crate is version-pinned,
  not a branch), reuses the shared engine, and the deviation is explicit and
  auditable in the ledger.
- **(c) `NOT_IMPLEMENTED` and drop from the 38-language claim** — would
  silently shrink the §32 claim. The owner keeps the 38-language surface and
  instead records the deviation where a reviewer can see it.

## 4. Validation (executed)

- `cargo test -p code-intelligence --test s2_languages` — the shared golden
  parity tests, including the eight deviation languages, pass.
- `cargo test -p code-intelligence --test s2_coverage` — the coverage gate
  accepts the ledger slices and their recorded deviations.
- `cargo run -p ukma-contract-check` — unchanged.
