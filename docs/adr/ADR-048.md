# ADR-048 — 實作範圍與 Profile 決策（O-01…O-04、O-07）

**Status: ACCEPTED**（owner 決策，2026-10-25）
**Spec references:** §8.1、§9.1、§9.3、§18（OPEN 項）、§22、§25.2、§28.2、§38.3（R4）、§43（DB-01、SCHEMA-01）
**Supersedes:** 無（本 ADR 填補 §18 明列的 `OPEN` 項，不改變任何既有不變條件）

## 1. Context

UKMA v1.2.3 §18 明確將數項範圍參數列為 `OPEN`：「上游鎖定 SHA、實際 crate mapping、首發語言集合、首發 PDF/OCR 覆蓋率、第一組 DB Adapter、embedding profile 與 SLA」。S0/S1 已鎖定 SHA 與 crate mapping；其餘四項與 legacy runtime 去留（O-07）須在 P1–P6 開工前定案，否則 G2/G3/G4/G5/G7 的判定範圍無法固定。

本 ADR 記錄 owner 於 2026-10-25 的決策，並**如實記錄其工作量與風險後果**——選擇最大覆蓋範圍會顯著放大 P1/P3/P4/P10 的規模，這不是規格保證，而是排程事實。

## 2. Decisions

| ID | 決策 | 具體範圍 |
|---|---|---|
| **O-01** | 首發語言集 = **上游鎖定基準的全部 38 個 parser** | `bash, c, clojure, cobol, cpp, csharp, css, dart, dockerfile, elixir, elm, erlang, fortran, go, groovy, haskell, hcl, java, julia, kotlin, lua, objc, ocaml, perl, php, python, r, ruby, rust, scala, solidity, swift, tcl, toml, typescript, verilog, yaml, zig`（依 `f:\codegraph-workspace\codegraph-reference\crates\codegraph-*` 實測清單，排除非語言 crate `harness / memory / parser-api / server`） |
| **O-02** | Document 覆蓋 = **Markdown 完整 + PDF 文字層 + DOCX**；**OCR 明確 NOT_IMPLEMENTED** | 未解析影像/PAGE 區域 MUST 記 `diagnostics` 並使 `completeness=partial`；不得臆測內容（§9.1） |
| **O-03** | DB Profile = **hybrid** | Adapter A = filesystem + SQLite（embedded）；Adapter B = PostgreSQL（sql）；Adapter C = Qdrant（vector）+ Neo4j（graph）（hybrid）。三者皆通過同一組 Port Contract Tests |
| **O-04** | Embedding profile = **BGE-M3 1024d 多語**；`SM=1024 / EM=512 / WM=256` 截斷**須經本地品質測試核准**才可啟用 | 未通過品質測試前 MUST 使用原維度或獨立 projection profile；維度/模型變更即建新 Index Generation 並原子切換 alias（§25.2、ML-003） |
| **O-07** | legacy `crates/ukma-code-runtime` = **標 deprecated，P3 完成後移除** | 其職責由 `code-intelligence`（解析/索引）與 `storage-adapters`（持久化）承接；移除前不得新增功能 |

### 2.1 ADR-047（System API 形狀）

同日核准 `system.capabilities / get_operation / get_job / cancel_job` 的 wire 形狀（見 ADR-047）。`system.*` 不再因形狀未定而 blocked。

## 3. Verifiable invariants

1. **O-01**：`crates/code-intelligence` 必須能對 38 種語言各產出一份 golden parity 報告；`CODE-001` 的判定集合為 38 語言，任一語言無 golden 報告即 `CODE-001 = FAIL`。語言清單變更（新增/移除）須修訂本 ADR。
2. **O-02**：`document.parse_preview` 對任一 PDF 影像區塊必須回 `parse_status=unparsed` + `diagnostics`；`DAPI-05` 須包含「OCR 未啟用」負向案例；`DOC-001` 不得以 OCR 結果作為通過條件。
3. **O-03**：`DB-002`（兩 adapter 同組 Port Tests）以 **A↔B** 為最低要求；加入 C 後 `DB-002` 擴為 A↔B↔C 三方等價。`DB-008`（無 RocksDB 完成 E2E）由 A 或 B 單獨滿足即可，但**兩個 profile 都不得載入 RocksDB**。
4. **O-04**：`EM-512/WM-256` 只有在 `ML-003`（截斷不相容切換 generation）與本地 recall/MRR 測試通過後才可標 `enabled`；未通過時 `embedding_profile` 記錄 `truncation: unapproved` 且使用 1024 維。
5. **O-07**：移除前 `ukma-code-runtime` 必須在 `docs/implementation-status.yaml` 標 `deprecated`，且其 9 個測試不得作為任何 release gate 證據。

## 4. Consequence（含誠實的工作量影響）

| 決策 | 影響階段 | 主要後果 |
|---|---|---|
| O-01 全 38 語言 | P3 | P3-WP1/P3-WP6 規模由「5 語言」放大到「38 語言」：38 份 parser 移植 ledger + 38 份 golden parity 報告；`CODE-001` 通過門檻提高一個數量級。建議維持「先建共用 ParserPort 骨架與 5 語言標竿，再批次擴充」的內部順序，但**驗收範圍仍是 38** |
| O-02 無 OCR | P4 | `DOC-001` 範圍明確縮小（利好），但必須在 `ParsedDocument.diagnostics` 誠實反映未解析區塊，否則 `DOC-002` 失敗 |
| O-03 hybrid | P1, P10 | 需 3 組 adapter 與跨 vendor projection lag 語意（`PENDING_PROJECTION`/`RETRY_SCHEDULED`/`DEGRADED_QUERY`/`FAILED_FINAL`）；`DB-002` 由 2 方等價升為 3 方等價；不得假設跨 vendor global ACID（§28.2） |
| O-04 BGE-M3 | P2, P6 | 需 embedding profile registry + 截斷品質測試閘門；向量空間混用由 `MODEL_PROFILE_MISMATCH` 拒絕 |
| O-07 移除 legacy | P0, P3 | P0 標 deprecated；P3 後刪除，須確認無 gate 依賴 |

**未承諾事項**：本 ADR 不承諾任何延遲、容量或 SLA 數字。§28.2 與 §29.6 的延遲/資源估算僅為設計估算，Release 前必須以實測 P50/P95/P99 與硬體配置記錄（ADR-030、§16）。
